Методика

По src/lib/assessment.ts официальный score считается только по scored-заданиям: закрытые quiz + API sandbox + SQL sandbox + DevTools sandbox. MANUAL_QA_SANDBOX, AUTOTEST_SANDBOX и open-text quiz не входят в процент.

Self review: open-text сверялся с ожидаемым смыслом вопросов; manual QA — с known bugs из src/lib/manual-qa-sandbox.ts; autotest — с expected scenarios из src/lib/autotest-sandbox.ts. Статус сессии не влияет на оценку.

Почему Не По Одному Score

Score

Официальный процент показывает закрытую базу и scored sandbox, но не включает manual QA, open-text и autotest.

Manual QA

Для QA intern важно уметь найти баг, описать шаги, actual/expected и попасть в реальные known bugs сценария.

Практика

API, SQL и DevTools дают сигнал технической готовности. На интервью их нужно проверить у всех top-5.

Что Проверить На Собеседовании

  • Всем top-5: короткий DevTools task, потому что никто из shortlist не закрыл DevTools sandbox.
  • Алексею: SQL projection/filter + autotest pseudocode.
  • Виктору: live bug report по known bug, чтобы проверить manual QA.
  • Нодиру: API request по спецификации и Charles/proxy troubleshooting.
  • Nodira: API + SQL + DevTools live, потому что manual/open сильнее, чем sandbox-практика.
  • Виталию: OOP/STLC/HTTP basics и API request.
